# Ordered macro origins: retained compiler-to-viewer handoff

This read-only component displays the existing compiler producer's actual
two-level ordered-program macro fixture. It does not run a compiler or debugger,
import an executable owner, grant authority, or complete M5/V3.

The source-only R81 proposal has not been compiled or tested. Its retained data
is historical actual output, not an execution of current main. A root-owned
fresh validation scope must qualify the parser, component and eventual route.

## Exact inputs and selection

The caller supplies the complete capture UTF-8, an independently selected
capture SHA-256, and a selection containing report SHA-256, canonical V17
identity, source-byte SHA-256 and expansion-chain identity. Changing source,
canonical owner or expansion does not silently rebind the selection.

The display envelope retains:

- The verbatim fe2o3-actual-ordered-macro-frames-fixture-v1 report.
- The verbatim independent original-route baseline JSON and complete canonical
  bytes in lossless lowercase hexadecimal.
- Exact fixture source bytes; optionally the exact device macro definition file.

The report and baseline must have identical prepared invocation records. The
source files are joined to their exact invocation paths, sizes and SHA-256
values. The baseline binary must match its independent original export pin.
The report's canonical identity is joined across its original owner, origin
and frame records; it is **not** replaced with the raw canonical-byte SHA-256.
The source/semantic/preflight/inventory and four declared source identities
remain separate.

Only ordered-program-nested-v32, gfx942:xnack-, wave64, the original
one-instruction descriptor and the exact two named nested frames are supported
here. This is intentionally narrower than the producer's 32-frame limit.
Other profiles, unavailable-dummy origin coordinates, unknown fields and
malformed or ambiguous records refuse. They do not fall back to another frame.

All fields are observations. The display cannot authenticate the compiler
process, rebuild its retained owner, verify the whole tool/source closure, or
grant source, proof, artifact, resume or launch authority. The old origin
record's macro_expansion_frames unavailable string is preserved: the separate
new producer supplies the frames, not a reinterpretation of that older field.

## Source navigation without invented mappings

Frames retain the compiler's innermost-to-outermost order and distinct
expansion identities. The last callsite joins the origin report's outermost
callsite; the first expansion joins its original expansion; the outer
expansion equals the inner callsite. The two source roles come from the
existing fixed producer fixture and exact original invocation, not from a
filename guessed from a digest.

Whole wrapper definitions and complete nested calls also match independently
derived, unique exact fixture anchors; a truthfully repinned header-only span
cannot substitute for the original full definition.

Every displayed excerpt has its UTF-8 byte bounds and one-based character
line/column coordinates rechecked against the selected file. Compiler file
identity is labeled independently from source-byte SHA-256. A definition
file may be omitted: its recorded coordinates and compiler identity remain,
but its path and excerpt are unavailable. The component never fetches that
file. Supplied but mismatching bytes are an error, not a missing-data fallback.

The component has keyboard-operable frame selection. It immediately hides
prior output when input changes and ignores late asynchronous results.
Selection has no source-edit, compiler, query-service or execution side effect.

## Deliberately unavailable

No final artifact was emitted in this macro campaign. Therefore there is no
HSACO/native/DWARF association to attach to these frames. The separately
qualified O0/O3 linked-line experiment is a different subject and is not
spliced into this capture.

These macro frames are not LLVM inline stacks, individual instruction
microsteps, physical-register contents, allocator lifetimes, a register
assignment proof, GPU observations, or a performance/memory measurement.
The reported whole-region origin does not identify each authored instruction.
No generic lifetime or compiler transformation model is implemented here.

## Bounds and validation

Capture UTF-8 is limited to 512 KiB, the actual producer wrapper to 128 KiB,
the baseline JSON to 16 KiB and each source to 64 KiB. Canonical bytes are
limited to 64 KiB; displayed excerpts to 4 KiB. The existing ordered-program
duplicate-key/unsigned-u64 JSON parser is reused, including its depth, node,
array and object limits. The consumer copies all selected strings and scalar
identities before the first asynchronous digest. Results are deeply frozen.

These are input/display bounds, not a browser heap, compiler allocation or
capture-overhead claim. Whole-owner memory and final artifact availability
remain unchanged.

## Existing debugger-page tutorial

The existing `#/debugger/source-isa-agent` page has a closed-by-default
**Trace retained whole-region macro origins** section. It adds no route,
evidence registry, compiler output or qualification gate.

To use the tutorial:

1. Open **Open retained macro frames** with the keyboard or pointer. The page
   selects the exact historical capture and four identities using independent
   literal pins; it does not trust identity fields supplied by the capsule.
2. Inspect **amdgpu_ordered_program**, the innermost frame. Compare its call site,
   macro definition and whole-region expansion. Byte positions and line/column
   coordinates refer to the retained source files, not live editor contents.
3. Select **ordered_program_wrapper**, the outer frame. Its call is
   `ordered_program_wrapper!(a, b, c)`; its definition covers the complete
   wrapper body. This is macro ancestry, not an LLVM inline stack or a debugger
   instruction step.
4. Open **Exact selected variant and baseline** to compare canonical V17
   identity, canonical-byte SHA-256, source-byte SHA-256 and expansion identity.
   These are different identities and are not interchangeable.
5. Close and reopen the panel to return to the innermost frame. Opening this
   panel does not change a separately selected ordinary-source operation or a
   recorded-program tutorial.

The page labels this capture **historical** and does not run a compiler, open a
debugger, launch a GPU, fetch a missing source file or change source. Final
artifact association, physical registers and allocation lifetimes stay
unavailable. No current-main, physical mapping, hardware or M5/V3 completion
claim follows from this example.

The new route controls exercise the real page, component and capsule, including
fixed identity display, keyboard selection, close/reopen reset, no fetch and
ordinary-source selection independence. The new Playwright spec uses the
existing route and desktop/mobile projects, light/dark themes, keyboard
operation, strict horizontal containment and retained screenshots. It does not
change browser flags, timeouts or evidence validators.
